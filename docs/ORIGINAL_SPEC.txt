==================================================
1. NON-NEGOTIABLE SECURITY REQUIREMENTS
==================================================

These requirements override all other instructions.

1. The product operates only on explicitly authorized company-owned or company-managed devices.

2. Every device must be enrolled through a visible, authorized installation and enrollment process.

3. The agent must never delete, quarantine, rename, encrypt, modify, or upload user files.

4. Never disable or modify:
   - Antivirus
   - Firewall
   - System updates
   - Security policies
   - System permissions
   - Browser protections
   - Disk encryption
   - Operating system configuration

5. Never perform exploitation, password extraction, credential dumping, privilege escalation, lateral movement, or network intrusion.

6. Never build a remote shell, arbitrary command execution endpoint, remote desktop, keylogger, screen capture, microphone access, or webcam access.

7. Never accept shell commands, PowerShell scripts, arbitrary SQL queries, or downloadable executable code from the dashboard.

8. Agent operations must be strictly limited to a hardcoded, audited collection allowlist.

9. Do not execute malware samples.

10. Do not silently install software.

11. Agent installation and optional background registration may create the minimum required application files and service configuration, with clear user consent. All actual security checks must be non-mutating.

12. Do not initiate an antivirus scan that may automatically quarantine or modify files.

13. Never claim that an endpoint is virus-free simply because no threats were reported.

14. Do not collect passwords, cookies, browser history, document contents, private photos, email bodies, or other unnecessary personal data.

15. Never display simulated cybersecurity results as actual scan results.

16. There must be no covert operation or hidden persistence mechanism.

17. Follow least privilege and privacy by design.

The server may request one or more of these predefined collectors, but never provide executable commands, SQL, scripts, or file paths for execution.

- Redact sensitive information before transmission.

9. AGENT ENROLLMENT & IDENTITY
==================================================

Build secure device enrollment.

Flow:

1. Administrator authenticates.
2. Administrator creates an enrollment request.
3. Server generates a random short-lived, single-use enrollment code.
4. Authorized user enters the code into the local agent installer or setup tool.
5. Agent establishes outbound HTTPS connection.
6. Server validates and atomically consumes the enrollment code.
7. Server issues a unique per-device credential.
8. Credential is stored using secure OS storage.
9. Device is associated with the correct organization.
10. Server records the enrollment event.

Enrollment tokens:
- Must be single-use
- Must expire
- Must be stored hashed on the server
- Must be rate-limited
- Must be scoped to one organization

Device tokens:
- Must be unique
- Must be revocable
- Must not appear in logs
- Must not be exposed to the browser
- Must be rotated using an authenticated protocol

Prefer Windows DPAPI and macOS Keychain for protected credential storage.

Do not use one shared fleet-wide secret.
